# Axis Atmos H200: safe host readiness

**Status:** source-only preflight. This is not a deployed Slurm partition,
persistent inference service, storage initialization, or GPU-isolation proof.

The approved temporary HPE Cray XD670 runs Rocky Linux 10.1 with eight
NVIDIA H200 GPUs. Maintain its host prerequisites through the isolated
Ansible playbook, **not** the existing EL9/A100 nvidia_gpu_host role.
The role does not install or replace NVIDIA drivers, restart services,
format disks, configure Slurm, or start vLLM.

## SSH and disconnection recovery

The Axis SSH principal can be regenerated by the portal. Keep it in private
inventory, not public Git. On the operator's workstation, SSH settings
ServerAliveInterval=30 and ServerAliveCountMax=6 can help with idle network
timeouts, but do not override broker-enforced session expiry. Use tmux for
interactive diagnostics; use managed systemd services for persistent workloads.
Never disable host-key verification to work around an Axis host-key warning.
Verify fingerprints with the Axis administrator.

A previous interactive-shell command had:
\`findmnt /srv/h200/science/scratch || exit 1\`
When no scratch filesystem was mounted, it executed \`exit 1\` and closed
SSH before fio ran. Use a guarded \`if findmnt --mountpoint ...; then ...;
else ...; fi\` instead. Do not paste unguarded \`exit\` or \`set -e\`
into an interactive administrator shell.

## Operator invocation

Run from an approved development/administration machine, not by cloning
repositories onto k8s-cp-01. Copy the example inventory into private inventory,
then set the currently approved Axis SSH endpoint/principal and all eight
expected GPU UUIDs. Verify the SSH host key independently.

From the repository \`ansible/\` directory:

\`\`\`bash
ANSIBLE_HOST_KEY_CHECKING=True ansible-playbook \
  -i inventories/private/axis-h200.yml \
  playbooks/axis-h200.yml --limit axis_h200 --check
\`\`\`

This role runs preflight checks and reads device signatures; no block-device
writes are performed. The repository's default ansible.cfg disables host-key
checking, so the explicit environment override above is essential.

If separately approved, \`axis_h200_manage_packages: true\` reconciles
diagnostic packages and NVIDIA Container Toolkit 1.20.1 without touching
the driver. Do not enable it until host-administration permissions are confirmed.

## Current observed hardware topology

- Inference candidate: GPUs 0–3, NUMA 0; nearby NVMe devices 4–7.
- Science candidate: GPUs 4–7, NUMA 2; nearby NVMe devices 0–3.
- Index-to-UUID-to-device-file mappings must be checked after reboot.
- At least one NVMe drive exposes GPT/PMBR signatures even though no
  filesystem is mounted. Do not assume drives are blank.
- A Podman CDI smoke test successfully exposed GPU 0 by UUID.
  This is not permission enforcement against other host processes.
- SELinux was observed disabled. Multi-user device isolation is not yet proven.
